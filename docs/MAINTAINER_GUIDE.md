# 项目维护说明

## 首次公开前

新建和导入项目均先保持私有。先执行 `python3 scripts/check_publication.py` 和全历史凭据扫描，再完成以下步骤。不要把内部交接记录、环境迁移说明、私人目录、旧验收数据或未完成的模板提示当作产品文档。第三方归属与许可声明必须保留。


1. 将 README 改成真实的项目说明，给出一个能够实际运行的最小示例。
2. 检查第三方内容的许可；本模板采用 MIT，并不自动覆盖其他代码的许可要求。
3. 添加与你的技术栈对应的测试与构建。通用卫生检查不能证明业务功能正确。
4. 在 Actions 确认默认分支的检查成功，再运行 `python3 scripts/configure_repository.py`。
5. 把业务检查的名称加入默认分支规则，再进行第一次发布。

## 每次发布

- 用干净环境执行文档中的安装和最小示例。
- 根据真实变更填写版本记录、兼容性说明与迁移方法。
- 从默认分支运行 Draft release，检查其指向的提交。
- 有二进制时应同时提供构建方式、校验值和平台信息。
- 核对 Release 草稿后再发布；不要通过移动已发布标签替换旧包。

## 维护节奏

每周处理可复现的问题，按使用需求调整路线图。只给范围明确、复现数据齐全的小任务标记 `good first issue`。
每月查看依赖更新；保持可以理解和回滚的变更范围。
若暂停维护，请在 README 写清状态和可用的替代方向，不必维持虚假的活跃度。
